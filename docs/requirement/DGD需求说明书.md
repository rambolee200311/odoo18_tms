# 1 业务概述与术语定义
## 1.1 核心术语
1. **DGD（Dangerous Goods Declaration）危险品申报单**
    欧盟法定强制随车单据，陆路场景遵循ADR法规格式，是路政、海关、ILT荷兰运输监管稽查的法定核验文件，与CMR公路运单配套构成危险品运输双凭证。
2. **ADR**：欧盟陆路危险品运输强制法规，规定货品分级、隧道通行限制、包装、申报文书规范。
3. **UN编号**：全球统一危险品编码体系，唯一标识危险物质品类、危险属性。
4. **transport.un_dictionary**：系统全局UN危险品基础字典库，存储所有ADR管制货品的标准合规参数，是DGD数据的权威数据源。

## 1.2 业务覆盖货物范围
1. 高频货品：UN3480锂离子电池（9类杂项危险品，日常出货主力）
2. 通用全覆盖：气溶胶、工业油漆、腐蚀性试剂、加压罐体、化工耗材等所有受ADR管制的危险货物
3. 支持同一份运输订单录入**多种不同UN危险品**，DGD自动多行渲染货物明细

## 1.3 法定价值说明
- CMR：货物物权、交接签收、承运履约凭证；
- DGD：危险品属性官方法律申报文件，无合规DGD上路会触发扣车、货物扣押、高额行政罚款、企业合规处罚。

# 2 业务现状痛点分析
1. **线下文档割裂**：依靠PDF/Word手工填制DGD，收发信息、UN参数、重量数据需要重复抄写，极易出现数据不一致的申报错误；
2. **数据孤岛问题**：DGD纸质/零散电子文件无法与`transport_order`运输订单绑定归档，事故溯源、海关稽查、监管审计调取资料效率极低；
3. **合规校验缺失**：人工维护UN等级、隧道代码、重量逻辑，依靠人工经验校验，误填会直接造成运输违规处罚；
4. **多货品适配困难**：多品类混装运输时，人工汇总总重、筛选最严格隧道限制代码极易出错；
5. **费用对账无凭证**：危险品运输产生的ADR资质服务费、押运费、合规附加费，缺少标准化DGD单据作为结算对账佐证材料；
6. **变更无留痕**：DGD填写错误后直接作废重制，无修改、作废操作日志，无法满足欧盟内控审计追溯要求。

# 3 整体建设目标与设计原则
## 3.1 建设目标
1. 依托订单内已维护的`transport_adr`危险品数据，自动预填充DGD全部表单字段，消除重复人工录入工作；
2. 复刻欧盟官方标准ADR-DGD双语（荷兰语+英文）版式，系统一键生成合规PDF文件，支持下载打印随车使用；
3. 搭建全生命周期管控：草稿→已生成文件→已归档→作废，所有操作永久留痕，禁止物理删除任何单据数据；
4. 配套标准化合规校验规则，拦截非法、不合规申报数据，降低运输被罚风险；
5. DGD电子档案归入订单统一归档池，与CMR、POD、T1/MRN保税文件、运输异常记录集中管理；
6. 支持DGD单据作为ADR相关附加费用的对账凭证，对接Carrier Settlement结算模块；
7. 架构预留IATA空运DGD模板扩展接口，后期新增空运危险品业务无需重构底层模型。

## 3.2 设计原则
1. **通用化优先**：锂电仅作为业务测试样例，所有模型、模板、校验逻辑不绑定具体货品；
2. **数据源头唯一**：DGD所有业务数据只读来源于订单&UN字典，禁止在DGD页面私自修改核心申报参数；
3. **版式法定固化**：ADR制式排版固定不变，仅货物明细区域动态渲染数据；
4. **审计不可篡改**：所有单据新增、修改、生成、作废动作全日志记录，数据仅状态作废、物理永久留存；
5. **低侵入集成**：复用现有TLMS订单、归档、权限体系，不新增独立存储与权限体系。

# 4 系统全域架构关联关系
```
┌─────────────────────────────────────────────────────────┐
│ transport.un_dictionary 【全局UN危险品字典库（权威数据源）】 │
└───────────────────────┬─────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│ transport_order 运输主订单                              │
│  ├─ 基础收发方、承运商、运输时间等通用信息               │
│  ├─ transport_adr 多行危险品明细子表（多UN货品混装）    │
│  └─ transport_dgd 【本模块：危险品申报单主表】          │
│        ├─ 自动生成标准PDF文件，存入订单归档附件池        │
│        ├─ 可被transport_exception运输异常绑定关联       │
│        └─ 可被Carrier Settlement结算账单行关联对账      │
└─────────────────────────────────────────────────────────┘
```
## 上下游联动说明
1. 上游：UN字典维护标准化危险品法规参数，订单业务人员仅选择UN编号即可自动带出全套合规数据；
2. 平级：DGD文件与CMR、POD、保税文件同属订单「合规资产」，被Context Loader按快照机制统一管理；
3. 下游：海关查验、运输事故异常可绑定DGD编号；承运商ADR杂费可关联DGD单据作为对账依据。

# 6 DGD完整业务生命周期流程
## 6.1 正常生成&归档主流程
1. 操作人员维护`transport_order`基础信息，并在`transport_adr`子表录入危险品，选择对应UN编号，系统自动从UN字典填充全部合规参数；
2. 订单勾选「包含危险货物」时，订单页面展示【DGD申报单】标签页，普通货物隐藏该入口；
3. 进入DGD页面，系统自动聚合所有货品数据、收发方、隧道代码、重量信息完成表单预填充；
4. 操作员核对系统带出数据，仅补充签署人、附加说明两个可变字段；
5. 点击【生成标准ADR-DGD PDF】，系统套用官方版式渲染文件并自动绑定至单据记录，状态由Draft变更为Generated；
6. 业务人员下载PDF打印、盖章后交由承运司机随车携带；
7. 该运输订单完成签收闭环后，系统自动将DGD状态变更为Archived归档状态，纳入长期档案管理。

## 6.2 单据作废流程
1. DGD数据有误需要重制 → 点击【作废单据】按钮；
2. 弹窗强制填写作废原因，确认后生成一条作废日志；
3. 原DGD状态标记为Void，数据物理保留不可删除；系统允许新建一份全新DGD单据绑定当前订单。

# 7 打印模板标准化规范
1. **版式基准**：严格按照业务实拍的ADR官方文档布局、双语表头（荷兰语主标题+英文对照标注）、区块分割线、字段排布位置固定不变；
2. **静态固定区域**：标题、栏目名称、签字区块、发货方固定信息全部固化在模板内；
3. **动态渲染区域**：货物明细表格支持单行/多行货品自动换行展示；合计重量、隧道代码由系统计算填充；
4. **输出格式**：仅生成标准PDF文件，版式不可被前端浏览器缩放篡改，适配A4纸张打印。

# 8 系统内置校验规则体系（保存&生成PDF双节点触发校验）
1. **UN编号合法性校验**：填写的UN编号必须存在于启用状态的UN字典内，拦截无效编码；
2. **重量逻辑校验**：单件净重 < 单件毛重，合计重量为明细行自动求和，禁止人工修改汇总数值；
3. **隧道代码值域校验**：仅允许填写 A / B / C / D / E 五种官方合规编码；
4. **危险格式校验**：危险等级+附属标识格式匹配ADR规范格式；
5. **状态约束校验**：已归档、已作废的DGD单据禁止再次编辑内容；
6. **订单唯一生效约束**：一个订单同一时间仅能存在一份非作废的有效DGD单据。

# 9 角色权限矩阵设计
| 角色账号 | 可读权限 | 可执行操作 | 严格禁止操作 |
|----------|----------|------------|--------------|
| 仓库操作员 | 查看本人所属订单DGD信息、预览/下载PDF | 新建草稿、编辑可变字段、生成PDF、作废本人创建单据 | 删除单据数据、修改系统自动带出的危险品参数 |
| 物流调度 | 全量DGD单据查看、PDF下载查阅 | 仅只读操作，无编辑、作废权限 | 改动任何DGD表单内容 |
| 结算专员 | 查看所有已归档DGD电子档案 | 仅可在费用账单绑定DGD单号作为对账凭证 | 修改申报数据、作废单据 |
| 财务人员 | 只读全部归档DGD PDF文件 | 无任何编辑操作权限 | - |
| 系统管理员 | 全量数据查看权限 | 维护UN字典库、维护DGD打印模板配置 | 人为篡改业务申报数据、随意作废正式单据 |

# 10 异常管控与作废管理规范
1. **运输异常联动**：在`transport_exception`异常记录（海关扣货、查验、危险品事故等场景）中，支持关联绑定对应DGD单据ID，留存稽查与处置凭证链路；
2. **作废刚性规则**：DGD作废不会删除原有记录，仅修改状态+写入作废日志，所有历史单据永久保存在系统数据库；
3. **归档锁定**：状态为Archived已归档的DGD，表单全部字段锁定只读，无法发起作废操作。

# 11 归档管理与合规审计要求
## 11.1 归档规则
DGD生成的PDF文件自动归入当前运输订单的统一归档目录，与CMR运单、POD签收凭证、MRN/T1保税文件、异常记录整合为一套完整订单合规档案。

## 11.2 审计强制要求
1. DGD新增、编辑、PDF生成、作废、下载全部行为写入操作日志，永久不可清理删除；
2. 电子档案存储周期遵循荷兰ILT监管法定留存年限；
3. 支持根据订单号、UN编号、时间段、承运商多条件检索DGD档案，一键导出整套订单合规资料包。

# 12 与Carrier Settlement承运结算模块联动规则
1. 承运商账单行（carrier.billing.line）录入ADR合规费、危险品押运、危险品申报等附加费时，支持关联绑定对应DGD单据ID；
2. 结算人员核对费用时，可直接跳转查看对应DGD电子文件，作为费用真实性的对账佐证材料；
3. 月度结算批次导出报表时，支持附带关联的DGD档案索引。

# 13 功能迭代优先级规划

4. 复刻官方ADR版式的PDF生成打印功能；
5. 全套字段校验规则 + 单据四状态流转管理；
6. DGD文件并入订单统一归档体系。

## P1 下一迭代优化功能

2. DGD多维度检索、批量PDF导出功能；
3. 预留IATA空运DGD模板扩展结构。

## P2 远期迭代增值能力
1. UN字典批量导入、官方ADR法规数据同步更新；
2. 承运商外部门户开放DGD电子文件在线查看权限；
3. DGD申报数据AI智能合规风险巡检。

# 14 非功能性需求
1. **兼容性**：完全适配现有Odoo数据结构，遵循Odoo model、权限、附件存储标准；
2. **性能**：单订单多货品（10行以内）PDF生成响应时间＜2s；
3. **数据安全**：DGD原始申报数据不可被前端篡改，所有修改行为留痕；
4. **上下文适配**：DGD归档文件适配系统Context Loader快照加载机制，统一纳入订单合规资产治理范围；
5. **可配置性**：发货方名称、签署地点等固定文字支持后台配置修改，无需修改代码。
